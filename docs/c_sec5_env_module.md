# 5장 환경 모듈과 예비 모듈 — 팀원 C 이행표

기준 2026-10-10 · 펌웨어 **`firmware/env_module/`**(`fw` = `env_module/1.0.0`, 5장 전용으로 따로 짠 펌웨어, 설명서는 그 폴더의 README).
기획서 5장의 표와 문단을 한 줄씩 나눠 **어떻게 지키는지**와
**실물로 남은 일**을 적는다. 실물 시험 절차의 자세한 단계는 [`c_hw_test.md`](c_hw_test.md)를 따르고, 결과는 이 문서의 기록칸에 적는다.

상태 표기: **구현** = 펌웨어에 들어가 PC 빌드·가상 시험으로 확인 · **실물 대기** = 부품·보드로 확인해야 함 · **기록** = 측정해 적어야 함.
실물로 확인하지 못한 항목은 "가상 시험·빌드 검증"으로 적고 실제 검증 완료로 적지 않는다.

## 1. 부품별 표시와 한계

| 우선순위 | 부품 | 기획서 표시와 한계 | 펌웨어 출력(JSON `payload`) | 화면 표시 | 하지 않는 것 | 상태 |
|---|---|---|---|---|---|---|
| 필수 | DHT11 | 환경 공기 온도·습도. 체온 대체 불가 | `air_temperature_c`, `humidity_pct`, `sensor_status.dht11`. 3회 연속 읽기 실패면 둘 다 `null`·`unavailable` | 공기 온도, 습도 | 체온·개인 과열 판정. 열 노출 주의(35°C 이상 생성, 34°C 이하 해제)는 **공기 온도 기준 환경 사건** | 구현 · 실물 대기 |
| 필수 | 조도 센서 | 상대 밝기. 보정 없이 lux 표시하지 않음 | `light_raw` (12bit ADC 원시값 0~4095) | 조도 (ADC 원시값) | lux 변환·표시 | 구현 · 실물 대기 |
| 추가 | 소리 센서 한 개 | 큰 소리 이벤트. 총성 판별·정확한 dB 제외 | `sound_detected` (DO 핀 인터럽트로 짧은 반응도 잡음) | 큰 소리 감지 | 총성 판별, dB 값 | 구현 · 실물 대기 |
| 추가 | 불꽃감지 센서 | 광학 반응 이벤트. 화재 확정 판정 제외 | `flame_detected` (적응 모드에서는 반응이 이어지는 동안 10초마다 보고) | 불꽃 감지 | 화재 확정·화재 경보 | 구현 · 실물 대기 |
| 추가 | 충격 센서 | 설치물 자체의 충격 | `shock_detected` | 설치물 충격 감지 | 병사 충격 판정(병사 `impact` 사건과 별개) | 구현 · 실물 대기 |
| 추가 | 리드스위치 한 개 | 자석 부착 덮개 등의 열림·닫힘 | `reed_closed` (50ms 디바운스, 바뀔 때마다 즉시 송신) | 리드 닫힘 / 열림 | — | 구현 · 실물 대기 |

- 감지(소리·불꽃·충격·리드)는 즉시 송신하고 같은 패킷을 광고 창 3개로 반복한다(같은 `seq`).
- **기본은 가상 데이터**다. 실물 센서를 확인하기 전에는 보드가 6개 센서 값을 가상으로 만들고 `source: "simulation"`으로 보낸다(10분 시나리오: 큰 소리·충격·리드·불꽃·열 노출·DHT11 실패·어두워짐).
- 실물을 확인한 뒤 `sensors real`로 바꾸고, 확인한 추가 센서만 `use sound on` 등으로 켠다(규격 1·12장: 추가 환경센서는 검증 후 적용). 꺼진 센서는 필드와 `sensor_status` 키가 JSON에서 빠진다.
- 가상 데이터는 보드에서 규격 값 규칙을 먼저 검사하고, PC의 C 시험 서버가 다시 검사·중복 제거한 뒤 통과한 것만 팀장 서버로 넘긴다(`--forward-lead`).

## 2. 전원·전압

| 기획서 문장 | 지키는 방법 | 확인 방법 | 상태 |
|---|---|---|---|
| 환경 노드는 USB 5V로 공급한다 | ESP32 DevKit의 USB 단자로만 전원을 넣는다(배터리·별도 어댑터 없음) | USB 전류계의 전압(V) 기록 | 실물 대기 |
| 센서 입력 전압과 출력 신호 전압은 별도로 확인한다 | 모듈마다 **VCC에 들어가는 전압**과 **출력 핀이 내는 전압**을 따로 잰다(아래 측정표) | 멀티미터, GPIO에 꽂기 전에 | 기록 |
| 5V 신호를 ESP32 GPIO·ADC에 직접 넣지 않는다 | 모듈 VCC는 보드의 **3V3 핀**에 연결한다(**5V·VIN 핀에 연결하지 않음**). 5V가 꼭 필요한 모듈은 출력에 분압(직렬 10kΩ + GND쪽 20kΩ → 약 3.3V) 또는 레벨 변환을 넣는다 | 출력 HIGH 전압이 3.3V 이하인지 확인한 뒤에 GPIO에 연결 | 기록 |
| 만능기판은 배선과 고정용이며 GPIO를 늘리지 않는다 | 멀티플렉서·IO 확장 칩을 쓰지 않는다. 센서 6개 = ESP32 GPIO 6개 직결(핀표) | 펌웨어 핀표와 실물 배선 대조 | 구현 · 실물 대기 |

**모듈별 전압 측정표** (전원 넣은 상태, 출력 핀은 아직 GPIO에 연결하지 않고 잰다)

| 모듈 | GPIO | VCC 연결 핀 | VCC 측정(V) | 출력 종류 | 출력 HIGH(V) | 출력 LOW(V) | 3.3V 이하? | 활성 레벨(`config.h`) | 조치 |
|---|---|---|---|---|---|---|---|---|---|
| DHT11 | 4 | 3V3 | | 디지털(단선 데이터, 풀업) | | | | — | 모듈에 풀업 없으면 10kΩ |
| 조도(포토레지스터 분압) | 34 (ADC1, 입력 전용) | 3V3 | | 아날로그 | 가장 밝을 때: | 가장 어두울 때: | | — | |
| 소리 DO | 27 | 3V3 | | 디지털 | | | | `SOUND_ACTIVE_LEVEL` HIGH | |
| 불꽃 DO | 26 | 3V3 | | 디지털 | | | | `FLAME_ACTIVE_LEVEL` LOW | |
| 충격 DO | 25 | 3V3 | | 디지털 | | | | `SHOCK_ACTIVE_LEVEL` HIGH | |
| 리드스위치 | 33 | 없음(내부 풀업 3.3V) | — | 접점(핀–GND) | 열림: | 닫힘: | | `REED_OPEN_LEVEL` HIGH | |

- 활성 레벨은 모듈마다 다르다. 반응할 때 출력이 HIGH인지 LOW인지 재서 `config.h`를 맞추고, 바꾸면 펌웨어 README 핀표도 고친다.
- 조도: ESP32 ADC는 기본 감쇠에서 약 3.1V 이상이면 4095 근처로 포화된다(정확한 값은 보드마다 다름). 밝은 곳에서 `light_raw`가 4095에 붙어 있으면 분압 저항을 바꾼다.
- 출력 HIGH가 3.3V를 넘으면(5V 공급 모듈) GPIO에 꽂지 말고 분압을 넣은 뒤 다시 잰다.

기획서: 예비 WROOM은 **같은 환경 펌웨어**를 준비한 교체용으로 둔다. ID는 부록 A 표의 `0x32` = `env_02`(B 확정 대기).

| 단계 | 할 일 | 확인 | 상태 |
|---|---|---|---|
| 1. 업로드 | `firmware/env_module`을 **그대로** 업로드하고 시리얼로 `id env_02`(NVS에 저장, 자동 재시작). 소스는 고치지 않는다 | `diag on` 뒤 부팅 줄 `"node_id":"env_02"`, `"fw":"env_module/1.0.0"` | 실물 대기 |

| 3. 되돌리기 | 다시 env_01로 쓸 때는 `id env_01`(또는 `factory`) | `config`의 `saved_node_id` | — |
| 4. 보관 | 보드에 "env_02 / env_module 1.0.0 / 커밋" 라벨 | 기록표 | 기록 |

## 6. 스캔·보고로 늘어난 소비전력·송신량

기획서: 스캔과 보고로 증가한 소비전력·송신량도 기록한다. `profile base`(스캔 끔) 10분 → `profile full`(스캔 켬) 10분. 바꿀 때마다 앞뒤 `stats`가 자동으로 남는다.
`stats`의 `tx.anchor_observation`·`tx.anchor_bytes`가 앵커 보고로 늘어난 송신량이다.
송신량은 `report.py` 송신량 표에서, 전압·전류는 USB 전류계에서 옮긴다. 소비전력(mW) = 전압(V) × 평균 전류(mA).

| 구간 | `tx_mode` | 스캔·앵커 보고 | 시간(s) | 패킷/분 | 바이트 | 앵커 보고 수 | 전압(V) | 평균 전류(mA) | 소비전력(mW) | 기준(A) 대비 증가 |
|---|---|---|---|---|---|---|---|---|---|---|
| A (기준) | fixed | 끔 | | | | 0 | | | | — |
| B | fixed | 켬 | | | | | | | | 전력 +   mW · 송신 +   패킷/분 |
| C | adaptive | 켬 | | | | | | | | |

- 소비전류는 소프트웨어로 잴 수 없다. 전류계 값을 직접 읽는다.
- `stats`의 송신량(`tx.*`)은 펌웨어의 논리적 기록이다. 실제 광고 이벤트 수·RF 방출량으로 적지 않는다(그 값은 스니퍼로 잰다, 규격 12장).

## 7. PC에서 이미 확인한 것 (실물 아님)

| 항목 | 방법 |
|---|---|
| 가상 센서 보드 11분(시나리오 한 주기 + 1분)의 USB 줄이 모두 규격 v1(오류·경고 0), `seq` 1부터 빈틈없음 | `pc/tests/test_env_module_contract.py` (펌웨어 소스를 PC에서 빌드해 실행) |

| 펌웨어 빌드 | arduino-esp32 3.3.12, `esp32:esp32:esp32`, 경고 없음(프로그램 공간 86%) |
