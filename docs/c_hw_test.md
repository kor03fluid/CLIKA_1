# 팀원 C 실물 시험 절차와 기록표 (환경 노드·앵커)

하드웨어가 도착하면(종료 6~4시간 전) A·B와 병렬로 진행한다. 결과는 맨 아래 기록표에 적고, 로그 폴더와
`report.py` 결과를 함께 인계한다. **실물로 확인하지 못한 항목은 "가상 시험·빌드 검증"으로 적고 실제 검증 완료로 적지 않는다.**

서버는 두 개다. **공식 관제는 팀장 서버**(`node server.mjs`, `http://localhost:8080`, 게이트웨이 COM은 팀장의
`serial_bridge.py`가 연다). C의 측정에는 **C 시험 서버**(`pc/server.py`, `http://localhost:8090`)를 쓴다.
팀장 서버는 아직 `anchor_observation`을 받지 않고 장치 진단 줄(`stats`)도 보관하지 않기 때문이다.
**같은 COM 포트는 한 프로그램만 연다**(Arduino 시리얼 모니터 포함).

필요한 것: ESP32 WROOM 2대(env_01, 예비 env_02), DHT11, 조도(포토레지스터+분압 저항), 소리·불꽃·충격 모듈,
리드스위치와 자석, USB 케이블, USB 전류계(소비전류 기록), 노트북(서버), 휴대폰(같은 Wi-Fi).

## 1. 전원 넣기 전 배선 확인

- 핀은 [`firmware/env_node/README.md`](../firmware/env_node/README.md)의 핀표를 따른다. 바꾸면 `config.h`와 README를 함께 고친다.
- 모듈 VCC는 3.3V. **5V 출력 신호를 GPIO·ADC에 직접 넣지 않는다**(5V 공급이 필요한 모듈은 분압·레벨 변환).
- 조도 분압 출력이 3.3V를 넘지 않는지 멀티미터로 확인한다(GPIO 34, ADC1).
- 디지털 모듈의 활성 레벨을 확인해 `config.h`의 `SOUND/FLAME/SHOCK_ACTIVE_LEVEL`을 맞춘다(지금 값: HIGH/LOW/HIGH).

## 2. 업로드와 단독 확인

빌드·업로드는 펌웨어 README의 "빌드". 먼저 시리얼 모니터(115200bps)로 본다. C 시험 서버가 포트를 잡은 뒤에는
그 화면의 **장치 명령** 칸으로 같은 명령을 보낸다.

| 항목 | 방법 | 기대 결과 |
|---|---|---|
| 부팅 | 리셋 | `# {"type":"boot",...}` 진단 줄 |
| DHT11 | 켜고 기다림 | 약 3초 뒤 첫 `environment`. `air_temperature_c`·`humidity_pct`가 숫자, `sensor_status.dht11: "ok"` |
| DHT11 분리 | DATA 선 뽑기 | 약 6초(3회 연속 실패) 뒤 온도·습도 `null`, `dht11: "unavailable"` |
| 조도 | 손으로 가렸다 뗌 | `light_raw`가 400 이상 바뀌면 적응 모드에서 송신(값 변화 송신은 최소 3초 간격) |
| 소리 | 손뼉 | `sound_detected: true` 패킷이 바로 나감(3회 반복 광고, USB에는 한 줄) |
| 충격 | 책상 두드림 | `shock_detected: true` |
| 불꽃 | 안전 수칙에 따라 짧게 | `flame_detected: true`, 반응 중에는 주기 10초 |
| 리드스위치 | 자석 붙였다 뗌 | `reed_closed` true/false가 바뀔 때마다 바로 송신(3회 반복) |
| 열 노출 | `vtemp 38` → `vtemp off` | `event`(`heat_exposure`)와 `environment`가 `source: "simulation"`. 끄면 다시 `device` |
| 명령 | `stats`, `mode fixed`, `anchor off` | `stats` 진단 줄의 `tx_mode`·`anchor_enabled`가 바뀜 |

## 3. PC 연동

**팀장 서버(공식)** — 환경 노드 데이터가 BLE → 게이트웨이(B) → 팀장 서버로 들어오는지 확인한다(팀장 현장 체크 5번 지원).

- 팀장 화면에 `env_01`의 `environment`가 보이고, `vtemp 38` 동안은 가상(`simulation`), 끄면 실측(`device`)으로 구분되는지.
- `vtemp 38`로 생긴 `heat_exposure` 사건이 노트북·휴대폰에 같이 보이는지(환경 노드가 사건을 직접 만든다).

**C 시험 서버(측정용)** — 환경 노드 USB를 연다.

```sh
cd pc
python server.py --serial <환경 노드 포트>
```

- `http://localhost:8090/`에서 `env_01`이 "연결", "최근 무효·경고 패킷"이 비어 있는지 확인.
- 5단계의 경로별 수신률을 잴 때만 팀장 브리지를 잠시 멈추고 게이트웨이 포트도 함께 연다:
  `python server.py --serial <게이트웨이 포트> --serial <환경 노드 포트>`. 끝나면 팀장 브리지를 다시 켠다.

## 4. 앵커 연동

- 병사 노드(A)를 켜면 "앵커 관측" 표에 `halo_01`·`halo_02`가 RSSI·경과와 함께 나온다.
- 중계 경유 패킷은 관측하지 않는다(`stats`의 `rx_relayed_skip`이 늘고 관측 표는 그대로).
- 거리·위치를 바꿔 가며(예: 1m, 5m, 벽 너머) 각 2분씩 두고 위치와 시각을 적는다. 구역 추정은 팀장 담당이므로
  `report.py`의 앵커 RSSI 표를 넘긴다.
- **앵커 시험 모드**(A의 가상 센서 보드): 가상 표시(`0x02`)로 방송하는 A 보드를 켜고 `anchor test on`. 관측 표에 같은 병사 ID가
  `simulation`으로 따로 나오고, `stats`의 `anchor_test: true`, `rx_simulation`이 늘어야 한다. 중계 경유 가상 패킷은 여전히
  관측하지 않는다(`rx_relayed_skip`). 끝나면 `anchor test off`(가상 관측이 표에서 빠짐).

## 5. 동시 운용 수신 누락 시험 (10분)

센싱·스캔·보고를 모두 켠 기본 상태로 10분 둔다(병사 노드 정상 송신). 서버를 끈 뒤 또는 켠 채로:

```sh
python report.py logs/<시작 시각>
```

- **노드별 수신**: 노드마다 누락·손실%. 환경 노드의 USB 줄은 누락 0이어야 한다(0이 아니면 펌웨어 쪽 문제).
- **경로별 수신**: 게이트웨이가 환경 노드 BLE 패킷도 받으면 `env_01 / gateway_01` 줄에 USB 송신분 대비 수신률이 나온다.
- **환경 노드 송신량**: `버림`(큐 가득 참)·`광고실패`·`스캔재시작`이 0인지, `큐밀림`(자리가 없어 앵커 보고를 미룬 묶음 수)이
  얼마나 되는지.

## 6. 송신량·소비전류 비교

각 구간 10분. **구간 끝에 `stats`, 설정을 바꾼 뒤 다시 `stats`**를 보낸다. `report.py`의 송신량 표가 `stats` 사이를
한 구간으로 보고 `tx_mode`·앵커 상태를 붙인다. 설정을 바꾼 짧은 구간은 "전환 포함"으로 나오므로 무시한다.

| 구간 | 시작 명령 | 보는 것 |
|---|---|---|
| A 고정 · 스캔 끔 | `mode fixed`, `anchor off`, `stats` | 기준 송신량 |
| B 고정 · 스캔 켬 | `stats`, `anchor on`, `stats` | 스캔·보고로 늘어난 송신량(앵커 보고)과 전류 |
| C 적응 · 스캔 켬 | `stats`, `mode adaptive`, `stats` | 고정 대비 송신량. 중간에 감지 1~2회 넣어 즉시 송신 확인 |
| D 적응 · 스캔 끔 | `stats`, `anchor off`, `stats` | (시간 있으면) 적응 모드 기준 |
| 끝 | `stats` | |

- 소비전류는 소프트웨어로 잴 수 없다. USB 전류계로 구간마다 평균 전류(mA)를 읽어 기록표에 적는다.
- `est_adv`는 창 길이/광고 간격으로 계산한 **추정치**다. 실제 광고 이벤트 수·RF 방출량으로 쓰지 않는다.

## 7. 예비 노드 (env_02)

`config.h`의 `NODE_ID`를 `0x32`로 바꿔 빌드·업로드하고 2단계의 부팅·DHT11·명령만 확인한다. 교체할 때는 서버의
`--roster`에 설치 지점을 같이 등록한다.
