# C 회신 — 환경 노드·앵커 진행 현황과 PC 코드 합치기

기준 2026-10-10 · 저장소 `kor03fluid/CLIKA_1` `main`
실물(보드 USB·BLE)로 확인한 항목은 아직 없다. 아래 "완료"는 빌드 검증, 가상 시험, 펌웨어 코드를 PC에서 빌드해 돌린 시험까지다.
팀장 문서의 "처리 로그 사용자 현장 확인 대기"는 확인 완료로 반영했다.

## 2. 팀장 PC 코드와 겹치는 부분

펌웨어 시험용으로 만든 Python PC 코드(`pc/`)가 팀장 코드와 겹친다. **공식 PC는 팀장 코드로 하고, `pc/`는 C 시험 도구로만 쓴다.**
PC 쪽을 새로 만들지 않고, 환경 노드를 팀장 코드의 입력 인터페이스(`POST /api/ingest`, `serial_bridge.py`)에 연결한다.

| 기능 | 팀장 코드 | C `pc/` | 합치는 방법 |
|---|---|---|---|
| 관제 화면·SSE | 있음(공식) | 디버그 화면만 | 팀장 것 사용 |
| 입력 검증 | 있음 | `schema.py` | 팀장 것 기준. 환경 노드 출력이 팀장 검증을 통과하는지 C가 맞춘다 |
| 중복 제거·순서·두절 | 있음 | 있음 | 팀장 것 사용 |
| 사건 저장·복원 | 있음 | 저장만(복원 없음) | 팀장 것 사용 |
| 처리 로그 | 있음 | `rx.jsonl` | 팀장 것 사용. C 측정 도구가 팀장 로그(`data/telemetry.ndjson`)도 읽게 맞춘다 |
| USB COM 입력 | `serial_bridge.py` | 시리얼 입력 | 팀장 것 사용. 환경 노드 COM도 브리지로 연결 |
| `anchor_observation` 수신 | 거부 | 있음 | C 쪽 처리(규격 9장 검사, 앵커·병사·출처마다 최신 관측)를 팀장 코드에 넣는 것을 제안 |
| 가상 노드 | 있음 | 있음(가상 환경 노드·앵커 포함) | 팀장 것 사용. 필요하면 가상 환경 노드·앵커만 팀장 시뮬레이터에 추가 |
| 펌웨어 출력 시험 | — | `test_firmware_contract.py` | 펌웨어 JSON 출력 코드를 PC에서 빌드해 팀장 검증 로직으로 확인하도록 바꾼다 |

## 3. 연동할 때 맞출 점

| 항목 | 환경 노드 동작 | 팀장 코드에서 |
|---|---|---|
| `seq` | 부팅 안에서 패킷 종류·출처 공통의 한 번호열(규격 4장) | `vtemp` 시험 중에는 실측·가상이 번호를 나눠 쓴다. 출처별로 보면 순번 공백이 생기지만 손실이 아니다 |
| `heat_exposure` | 장치가 만든다 | 서버에서 온도로 따로 만들지 않기(중복 방지) |
| `# `로 시작하는 줄 | 장치 진단(데이터 아님) | 브리지에서 잘못된 JSON으로 콘솔에만 남으면 정상 |
| `transport` (환경 노드 USB 직결) | `gateway_id: "env_01"`, `route: "direct"`, `hop_count: 0` | 그대로 받기 |
| `heartbeat_interval_ms` | 적응 30000(두절 92초), 열 노출·불꽃 중 10000, 고정 5000 | 선언값으로 두절 판정 |
| 공중 송신 순서 | 사건·감지 패킷이 쌓인 일반 패킷보다 먼저 나간다 | 늦게 온 낮은 `seq`는 상태를 덮지 않으면 정상 |
| COM 포트 | 환경 노드 USB 1개, 게이트웨이 USB 1개 | 브리지를 포트마다 하나씩 켤지 코드 보고 결정 |

## 4. 코드를 받으면 할 일

1. 팀장 서버를 로컬에서 띄우고, 펌웨어 실제 JSON 출력과 가상 환경 노드 데이터를 `/api/ingest`에 넣어 통과 확인
2. `serial_bridge.py`가 환경 노드 출력 줄(진단 줄 포함)을 어떻게 처리하는지 확인
3. `anchor_observation` 수신 추가 코드를 제안(팀장 확인 후 반영)
4. C 측정 도구가 팀장 처리 로그를 읽게 맞추기

## 5. 요청

- 팀장 PC 코드 압축본
- `anchor_observation` 수신을 C가 팀장 코드에 넣어도 되는지, 팀장 쪽에서 할지
- B와 BLE 무선 형식 확정 일정
